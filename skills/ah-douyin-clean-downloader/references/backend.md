# 后端与维护说明

## 当前数据流

1. 从用户口令中只提取抖音官方 HTTPS 链接。
2. 跟随短链跳转，并再次验证最终域名。
3. 从长链或分享页提取作品 ID。
4. 读取抖音系元数据响应。
5. 按 `play_addr_h264`、`play_addr`、H.264 码率源的顺序选择播放地址。
6. 不读取 `download_addr`，不通过替换 URL 文字伪造无水印地址。
7. 清理博主昵称，建立或复用 `媒体库根目录/博主昵称/`。
8. 下载到博主目录中的 `.part` 临时文件，完成后原子替换为 MP4。
9. 优先用 `ffprobe` 验证；缺少 `ffprobe` 时只做 MP4 文件头验证。

## 网络和代理

- 默认直连，不猜测本机代理端口。
- 用户可显式传入 `--proxy` 或设置 `AH_DOUYIN_PROXY`。
- 如显式代理失败，会再尝试直连。
- 脚本不安装证书，不修改系统代理，不写入代理配置。

## 成本

解析和下载在本机完成，不使用付费解析 API、ASR 或视觉模型。除 Codex 自身用量外，只消耗本地网络流量、磁盘和少量计算资源。

## 已知边界

- 只能去掉抖音平台在分发阶段添加的角标水印。
- 作者上传前烧录的 Logo、字幕或贴片不会被移除。
- 当前版本不处理图集、私密作品、需登录作品和已删除作品。
- 博主分类默认使用当次元数据中的昵称；博主更名后可能建立新目录，第一版不自动合并历史文件夹。
- 平台接口可能变化；失败时先更新元数据端点和播放源字段，不要默认改用未知第三方解析站。

## 维护检查顺序

1. 运行 `doctor.py`，确认 Python 和 curl。
2. 使用用户自有的公开视频执行 `--metadata-only`。
3. 检查跳转后的链接是否仍包含作品 ID。
4. 检查元数据的 `aweme_list`、`video`、`play_addr_h264` 和 `play_addr`。
5. 使用合成固定数据更新单元测试。
6. 最后再进行一次真实下载和 `ffprobe` 验证。
