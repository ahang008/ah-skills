# Gemini 口播稿润色桥

把 Codex 当前任务中已经整理好的观点、事实、原话和风格要求交给 Gemini，让它负责中文口播表达，再由 Codex 核对事实和原意。

这是阿杭实际写稿过程中制作的试用 skill，名称为 `ah-gemini-script-polisher`。适合已有 Codex 上下文、想保留观点和经历、同时希望使用 Gemini 文风的创作者。

## 安装和调用

把下面这句话发给 Codex：

```text
安装 https://github.com/ahang008/ah-skills 中的 skills/ah-gemini-script-polisher
```

安装完成后新开一轮对话，发送：

```text
用 ah-gemini-script-polisher，把我们这次任务的观点、事实和我的原话整理成写作包，交给 Gemini 3.8 Flash 润色口播稿。保留我的意思，返回完整正文。
```

运行需要可控制浏览器的 Codex 环境、已登录且具有目标模型使用权限的 Gemini 官网账号，以及 Python 3。账号和模型在页面上核对，不由 URL 序号或模型自述推断。模型不可用时报告，不能冒称完成或自动换模型。

## 这座桥怎么工作

1. Codex 提炼当前任务的主题、受众、原稿、已确认事实和锁定原话，形成最小而充分的写作包。
2. 写作和润色选择官网 `3.8 Flash`；讨论这座桥的架构选择 `Pro`。这些是本次实际页面标签，菜单发生变化时重新核对。
3. 在独立写作对话中发送写作包，同一任务的继续和修订复用该对话。
4. 读取完整回答，检查任务编号、版本、首尾标识和字数，拒绝半篇稿、重复拼接或旧任务结果。
5. Codex 对照原材料核对事实、原意和口播可读性。有具体缺陷时给一次定点修订；通过后保留 Gemini 表达。

## 等待规则

- 普通写作或短架构答复无正文进展满 5 分钟，在原对话发送一次精确的“继续”。若界面正在生成且不能发送，先停止并核对停止状态，再继续。
- 继续后再等待一个 5 分钟无进展窗口；仍无响应则保留现场并报告，不无限催促。
- 已授权的 Deep Research 明确仍在研究时继续等最终报告，允许超过 20 分钟，不套用普通写作的 5 分钟停止规则。
- 等待分成不超过 60 秒的短段。研究计划、来源卡片和活动动画不等于最终报告。

## 已验证和未验证

- 2026-10-06 的官网 Flash 首轮返回了两篇内容拼接，完整性检查将其拒绝。原对话一次定点修订后返回 429 字完整试稿，完成文本完整性和事实边界核对。
- 响应检查脚本的 12 项完整、截断、串任务、错误版本、重复标识和长度测试通过；等待规则的 16 项指令检查通过。
- Pro 未返回可采用的架构建议。该试稿在 5 分钟阈值前返回，普通超时恢复和超过 20 分钟的研究等待没有实测。
- 首版只证明一次写作流程跑通，尚无对照实验支持“稳定提升写作效果”，也没有独立新会话的自动触发评测。

运行响应检查测试：

```text
python3 tests/test_response.py
```

## 使用边界和来源

该 skill 负责浏览器写作交接，不自动发布稿件，不购买模型权益，不包含登录绕过或第三方代购功能。网页权益、模型可用性和第三方报价分别判断；价格比较不属于正文完整性脚本的验证范围。

只传递本稿必要且已获授权的素材，不保存账号、Cookie、Token 或敏感文件。普通写作未指定 Gemini、通用研究和应用代码架构不自动触发。

规则与检查脚本由本次 Codex 和 Gemini 写作桥任务制作，未复制第三方桥接代码。Gemini、Codex、Python 和浏览器能力由对应提供方提供。
